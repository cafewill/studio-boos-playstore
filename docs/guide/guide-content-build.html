작성일: 2026년 11월 21일 · 작성자: 지순이(ChatGPT), 로컬 작업자 Bill(min@cafewill.com) · 호스트 nano

📖 개요

게임·학습·창작·이야기 활동을 빌드 없이 로컬 정적 서버에서 실행한다. 현재 60개 후보별 MVP 정의·공통 셸·7개 엔진·포털·구조/규칙 검증·브라우저 하네스를 구성했다. 설정 변형과 고유 메커닉·최종 완료를 구분한다. 실제 검증 상태는 루트 GLANCE.md와 test/ 기록을 따른다.

🧱 기본 스택과 구조

HTML/CSS + Vanilla JavaScript ES Modules를 사용한다. 학습 UI·폼·버튼은 DOM을 우선하고 그림·실시간 놀이에 Canvas 2D를 선택한다. Canvas 사용 시 조작 버튼과 상태 설명을 DOM으로 제공한다. Android 스마트폰·태블릿 Chrome과 데스크톱 Chrome을 우선 검증한다. Safari는 보조 호환성 검증 대상으로 둔다.

textdata/implementation/registry.json # 활성 배치 등록
contents/shared/                  # 공통 상태·저장·엔진·UI·디자인 토큰
contents/{slug}/content.js         # 생성 정의
contents/{slug}/src/main.js        # 생성 공통 부트스트랩
contents/{slug}/index.html         # 생성 진입점
contents/{slug}/README.md          # 생성 설명·권리 기록
contents/catalog.js               # 생성 사용자 카탈로그

구조의 정본은 공통 구조·유지보수 가이드다. 원작별 독립 엔진·개별 CSS·화면·저장 구현을 복제하지 않는다. 배치 정의를 편집하고 생성 명령으로 진입·카탈로그·설명을 함께 갱신한다. 신규 활동 유형은 정식 엔진·표시·검증 어댑터로 등록한다. 외부 CDN·서버·빌드 도구는 기본 사용하지 않으며 의존성이 필요하면 이유·버전·라이선스를 기록한다.

📐 구현 규칙

  • 공통 구조·상태·저장·입력 규약을 따른다. 개별 구현의 우회 분기를 추가하지 않고 정의·엔진 확장으로 처리하며 전체 계약 검사를 실행한다.
  • 저작권·지식재산권 가이드를 모든 구현·수정·검증에 적용한다. 콘텐츠 README에 요소별 출처·권리 근거·필수 고지를 기록하고 불명확한 자료는 사용하지 않는다.
  • 사용자 화면은 Fascinating UI 가이드를 필수 적용한다. 브라우저 기본 INPUT·SELECT 외형의 나열 대신 활동에 맞는 커스텀 UI를 구성하되 의미 있는 HTML과 표준 조작을 유지한다.
  • 색상·문구·네이밍은 아동 UX·안전 기준의 정서·표현 기준을 항상 적용한다. 콘텐츠·캐릭터·단계·버튼·접근성 이름까지 계획과 실제 화면을 대조하고, 변경 시 함께 갱신한다.
  • 시범은 반복·건너뛰기 가능하며 처음부터 긴 설명문을 요구하지 않는다.
  • 상태 전이와 정답·완료 판정을 렌더링에서 분리한다. 빠른 연속 입력으로 중복 점수·중복 진행이 발생하지 않게 한다.
  • 애니메이션은 requestAnimationFrame과 경과 시간으로 처리하고 탭 비활성 시 일시정지한다.
  • Pointer Events의 취소·포인터 이탈과 화면 회전을 처리한다. Canvas는 DPR·크기 변경·좌표 변환을 반영한다.
  • 새로고침 후 복원은 유효한 상태만 허용하고 버전 불일치·손상·저장 차단에 대응한다. 저장이 필수 실행 조건이 되지 않게 한다.
  • 접근성을 실제 DOM 의미·키보드·포커스로 구현한다. 포털로 돌아오기와 활동 종료는 항상 찾기 쉽게 둔다.
  • 콘텐츠 README에 연령·활동 목표·조작·실행·저장·삭제·에셋 출처·알려진 한계를 기록한다.

🚀 실행

bashpython3 -m http.server 7904 --bind 127.0.0.1

문서는 /docs/guide/guide.html, 향후 콘텐츠는 /contents/{slug}/에서 확인한다. ES Modules는 file:// 대신 HTTP로 실행한다. 정적 서버 접근 이후 외부 통신 없이 동작하는 것을 기본으로 하며, 설치형 PWA나 서버 없는 재접속 캐시는 별도 범위다.

JS가 생기면 node --check로 문법을 확인한다. 전체 규칙은 tools/logic/batch60.mjs, 실제 입력은 tools/play/batch60.mjs의 공통 시나리오로 검증한다. 추가 엔진·경계 사례는 공통 검사에 등록하되 구현을 그대로 되풀이하는 테스트보다 오답·생성 불변식·상태 복원 같은 위험을 검증한다. Chrome 모바일 에뮬레이션은 실제 Android 기기 검증을 대신하지 않는다.

결과는 test/{TS}-{slug}-check.md에 환경·절차·기대값·실제값·성공/실패/미실행·증거 경로로 남긴다. 스크린샷만으로 기능 검증을 대체하지 않는다. 아동 직접 관찰이 없으면 개발자 시나리오 검증으로 명시한다.

🔄 완료 처리

콘텐츠 README에 컬러 컨셉·이름의 의미·대표 피드백 문구와 검토 결과를 기록한다. 생성기 정본을 갱신하고 콘텐츠 README·카탈로그를 재생성한다. GLANCE.md와 계획·리뷰 목차도 갱신한다. 포털 도입 후 카탈로그에는 slug, 자체 이름, 유형, 연령, 짧은 설명, 경로, 태그, 자체 썸네일을 관리한다. 사용자 화면에 테스트 결과·개발 상태·원작 상표를 표시하지 않는다.
