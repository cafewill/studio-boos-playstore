# ✨ Fascinating 커스텀·반응형 UI 가이드

## 📖 개요

모든 사용자용 콘텐츠·포털·보호자 화면에서 간결하고 직관적인 커스텀 UI를 기본으로 한다. 브라우저 기본 INPUT·SELECT 등의 외형을 그대로 나열하는 대신 활동의 의미와 연령에 맞는 시각 언어를 구성한다. 이 문서는 모든 사용자 화면의 구현 기준이며, 현재 콘텐츠와 검증 상태는 루트 `GLANCE.md`를 따른다.

오빠가 제공한 스팍의 “Fascinating”(페시네이팅) 쓰임새를 디자인 방향으로 삼는다. 낯선 현상을 마주했을 때의 절제된 놀라움과 호기심, 한쪽 눈썹을 들어 올리는 듯한 작은 반응을 UI의 발견 경험으로 해석한다. 원작 캐릭터·대사·외형을 제품 테마로 복제하라는 의미는 아니다.

## 🧩 주요 내용

### ✨ Fascinating 경험의 기준

- 무엇을 할 수 있는지 먼저 이해되고, 직접 눌러 본 뒤 작은 변화가 발견되도록 설계한다. 조작 결과는 즉시 알아볼 수 있게 표시한다.
- 한 화면의 주요 행동은 하나로 명확히 두고 보조 행동은 시각적 우선순위를 낮춘다. 설정은 필요한 순간에 단계적으로 보여 준다.
- 예: 씨앗 카드를 탭하면 선택 테두리와 짧은 설명이 나타나고 활동을 완료하면 새싹 하나가 조용히 펼쳐진다. 변화는 활동의 의미를 설명해야 한다.
- 소리·애니메이션을 꺼도 선택·진행·완료를 이해할 수 있게 한다. 무작위 보상·깜짝 공포·큰 효과음·자동 재생·계속하기 압박을 발견의 재미로 포장하지 않는다.
- 색·모서리·그림·움직임은 정서·표현 기준과 일관되게 구성한다. 과도한 장식으로 버튼·정답·도움·종료를 찾기 어렵게 하지 않는다.

### 🎨 익숙한 조작과 다양한 놀이 표현

일관성의 핵심은 코드 알고리즘·설계 패턴·상태와 입력 계약·기본 조작이다. 화면 전체를 같은 배치와 그림으로 만드는 것을 의미하지 않는다. 아동이 조작법을 다시 배우지 않으면서도 새로운 장면과 활동을 발견하도록 설계한다.

| 일관성을 유지할 요소 | 활동별 다양성을 설계할 요소 |
|---|---|
| 홈·도움·중단·재개·소리의 의미와 위치 원칙 | 정원·작업대·스케치북·악기 등 활동 공간 |
| 터치 영역·키보드·포커스·선택 피드백·읽기 쉬운 대비 | 장면의 구도·소재·그림·색 조합·여백과 배치 |
| 상태·저장·복원·규칙·입력 처리 계약 | 누르면 피어나기·조립하면 이어지기 등 활동에 맞는 반응 |
| 공통 토큰과 재사용 가능한 조작 컴포넌트 | 활동이 요구하는 표시 어댑터와 테마 구성 |

- 색·제목만 교체한 화면을 시각적으로 독립된 놀이로 완료 처리하지 않는다. 같은 엔진을 사용해도 활동 목표에 맞는 장면과 주요 조작의 차이를 계획한다.
- 다양성은 무작위 장식·번쩍임·잦은 위치 변경으로 만들지 않는다. 아동이 활동의 의미와 조작 결과를 이해하는 데 도움이 되는 차이를 만든다.
- 검토에서는 대표 화면을 나란히 비교해 활동을 구별할 수 있는지 확인한다. 같은 조작의 의미가 달라지거나 장식 때문에 도움·중단을 찾기 어려워지면 수정한다.
- 현재 포털의 그림 개선과 개별 등록 활동의 시각 다양성 개선은 별도 범위다. 기존 활동은 공통 셸을 사용하는 MVP이며 확장 활동에는 낱말 그림책·생활 순서 작업대·소품 공간의 표시를 추가했다. 같은 표시 안의 주제 변형도 포함한다. 화면별 다양성 및 실제 아동의 흥미 지속은 아직 검증하지 않았다.

### 🖼 소개·그림은 실제 활동에서 가져오기

- 카탈로그 소개는 각 정의의 description을 사용한다. 공통 목표 문장이나 ‘선과 점으로 자유롭게’ 같은 문장을 제목만 바꿔 반복하지 않는다. 무엇을 보고 어떤 조작을 하는지 실제 구현 범위 안에서 설명한다.
- 카드·시작 미리보기는 `contents/shared/ui/artwork.js`가 실제 설정을 받아 그린다. 낱말은 등록된 단어·그림 문자, 공간은 등록된 소품, 수 활동은 연산·수 범위, 조립은 참고 조각을 보여 준다. 엔진 이름만으로 무관한 꽃·도형 그림을 재사용하지 않는다.
- 17개 미술 안내선은 DRAWING_PATHS를 정본으로 삼아 SVG 미리보기와 실제 Canvas Path2D가 공유한다. 잎·구름·집·연·나비·눈송이 등이 다른 윤곽을 갖도록 하며 기존 획 저장 형식은 유지한다.
- presentation은 선택적인 표시 메타데이터다. 기존 정의·저장 상태의 호환을 위해 없어도 실제 params 기반 기본 표시를 제공한다. 로직·난이도·정답은 표시 코드에서 바꾸지 않는다.
- 같은 규칙과 같은 설정이 실제로 동일하면 서로 다른 게임처럼 과장하지 않는다. 주제 변형의 소개 개선과 고유 메커닉 추가를 구분한다. 정적 그림 생성 검사는 실제 렌더·흥미 지속 검증이 아니다.

### 🌷 포털의 시각적 발견 기준

- 포털은 같은 도형 세 개를 반복하는 카드 목록에 머물지 않는다. 첫 화면에 직접 조작하는 작은 정원을 두고, 씨앗 심기·꽃 색 변경의 결과를 그림과 상태 문구로 함께 전달한다. 자동 재생·소리·무작위 보상은 사용하지 않는다.
- 살구·노랑·하늘·초록 계열을 활동 그림의 강조색으로 사용하고 본문·조작은 짙은 초록으로 읽기 쉽게 구성한다. 색의 발달 효과를 단정하지 않는다.
- 수·모양, 미술, 조립, 소리, 시간, 감정, 명령의 활동을 서로 다른 자체 SVG 그림으로 표현한다. 같은 엔진의 변형까지 모두 고유 그림이라고 표시하지 않는다.
- 큰 제목과 여백, 조작 가능한 대표 그림, 활동별 카드, 검색·필터 순으로 탐색 흐름을 만든다. 포털 그림은 `contents/portal-art.js`, 외형은 `contents/portal.css`에 모아 유지한다. 생성 카탈로그와 개별 콘텐츠 파일은 직접 수정하지 않는다.
- hover는 보조 표현이다. 키보드·터치만으로 정원 조작·검색·필터·활동 진입이 가능해야 하며 모션 감소에서는 움직임을 제거한다. 조작 없는 화면 캡처와 실제 입력·모바일 검증을 구분한다.

### 🛠 30개 확장의 활동별 표시

재료 작업대는 주문표·그릇·재료 트레이와 되돌리기, 리듬은 3줄×4박 격자와 한 박씩 확인, 조합 연구대는 두 선택 자리·결과·조합 수첩, 프레임 편집기는 4장 스트립·3×3 위치·수동 넘기기로 구성한다. 카드·시작 미리보기는 실제 재료·트랙·요소·기호를 사용하고 공통 꽃 그림으로 대체하지 않는다.

입력·완료·쉬기·저장은 동일 셸 계약을 유지한다. 장면·레이아웃은 활동의 의미를 드러내도록 다르게 구성한다. 소리·자동 움직임·드래그 없이도 실제 버튼과 키보드로 완료할 수 있어야 한다. 리듬의 수정 후 재확인, 프레임의 편집 후 재검토 조건을 화면 문구로 설명한다. 실제 렌더·터치·보조기술 검증은 정적 HTML 생성과 구분한다.

### 🧱 일관된 UI 구현 경계

[공통 구조 가이드](guide-content-architecture.md)에 따라 셸·토큰·버튼·포커스·대화상자·저장 조작을 한 곳에서 유지한다. 개별 콘텐츠 CSS나 main.js에 같은 UI를 복사하지 않는다. 테마·목표·문항·허용 색과 같은 차이는 정의로, 새로운 상호작용은 정식 유형 어댑터로 표현한다. 공통 변경 후 모든 영향 콘텐츠를 검사한다.

### 🧩 기본 폼을 활동에 맞는 UI로 구성

| 용도 | 우선 구성 | 의미·조작 기준 |
|---|---|---|
| 소수 옵션 선택 | 아이콘·짧은 설명이 있는 선택 카드, 분할 선택 버튼 | 가능하면 실제 radio와 label을 스타일링, 선택 상태는 색·테두리·표시로 전달 |
| 화면 전환 | 제목이 명확한 탭 | 실제 패널 전환일 때만 탭 의미 적용, 단일 값 선택과 구분 |
| 켜기·끄기 | 라벨과 상태가 보이는 토글 | checkbox 또는 상태를 전달하는 버튼 사용 |
| 수량 조절 | 값 표시와 늘리기·줄이기 버튼 | 최소·최대·현재 값과 비활성 상태 안내 |
| 연속 값 조절 | 큰 손잡이와 현재 값이 있는 슬라이더 | 실제 range를 우선 스타일링, 키보드·단계 조절 제공 |
| 텍스트 입력 | 명확한 라벨·넉넉한 입력 영역·보조 안내 | 실제 input·textarea의 입력·자동완성·가상 키보드 의미 유지, placeholder만으로 라벨 대체 금지 |
| 긴 목록 선택 | 검색·목록 또는 적합한 선택 패널 | 옵션 수·연령·화면 폭에 따라 판단, SELECT 대체 시 키보드·포커스·스크린리더 동작까지 구현 |
| 실행·되돌아가기 | 자체 스타일의 의미 있는 버튼·링크 | 동작은 button, 이동은 a, 반복 터치와 중복 실행 처리 |

커스텀은 시각 표현과 상호작용을 활동에 맞게 설계한다는 뜻이다. 의미 있는 HTML 요소의 동작을 유지하면서 CSS로 다듬는 방식을 우선한다. 클릭 가능한 div만으로 폼을 재구현하거나 사용자 입력 의미를 제거하지 않는다. 날짜·파일·모바일 선택 등 OS 고유 조작이 더 적합하면 기본 컨트롤을 사용할 수 있으며 이유를 계획에 기록한다.

### 🎨 컴포넌트 시각 규칙

- 색상·간격·모서리·타이포그래피·그림자·포커스 스타일을 CSS custom properties로 정의하고 콘텐츠 안에서 일관되게 사용한다.
- 기본·호버·키보드 포커스·눌림·선택·비활성·오류 상태를 정의한다. 호버에만 설명이나 핵심 조작을 숨기지 않는다.
- 주요 터치 영역 최소 48×48 CSS px와 간격 8px 목표를 유지한다. 시각적으로 간결하게 보여도 누르기 쉬운 영역을 확보한다.
- 선택·오류는 색 외에 체크·아이콘·문구 등으로 구분한다. 비활성 상태와 가능한 다음 행동을 이해할 수 있게 한다.
- 움직임은 짧고 목적 있게 사용하며 반복·동시 움직임을 제한한다. `prefers-reduced-motion`에서는 움직임을 줄이고 상태 표시를 유지한다.

### 📱 반응형 레이아웃

- 모바일부터 설계하고 고정 화면 크기에 맞춘 축소 대신 카드 수·정렬·간격·보조 정보 배치를 바꾼다. 학습·놀이 대상과 주요 행동은 가장 먼저 보이게 한다.
- Grid·Flex와 유동 폭을 사용하고 콘텐츠 길이에 따라 줄바꿈한다. 고정 높이로 문구·버튼·선택 목록을 자르지 않는다.
- 세로·가로 방향, 태블릿·데스크톱, 긴 한국어 문구와 글자 확대를 확인한다. 반응형 전환 중 선택값·진행·키보드 포커스를 잃지 않게 한다.
- 모바일 가상 키보드와 안전 영역을 고려해 입력·확인·닫기 버튼을 가리지 않는다. 고정 하단 버튼은 본문을 덮지 않도록 공간을 확보한다.
- 선택 패널·모달은 화면 안에서 조작·스크롤·닫기가 가능하게 한다. 모달은 열릴 때 포커스를 이동하고 닫을 때 원래 위치로 복원하며 키보드 이탈을 관리한다.
- 드래그·스와이프 없이도 주요 활동을 완료할 수 있게 한다. 화면 회전·포인터 취소·패널 닫기 이후 상태를 복구한다.

### 🗒 계획·리뷰에 남길 항목

1. Fascinating 포인트: 어떤 행동이 어떤 발견으로 이어지는지 한 문장으로 설명한다.
2. 화면별 주요 행동, 컴포넌트 종류·선정 이유, 기본 컨트롤 유지가 필요한 예외를 기록한다.
3. 컴포넌트 상태·접근 가능한 이름·선택 의미·포커스·키보드·터치 동작을 정의한다.
4. 모바일·태블릿·데스크톱 배치, 긴 문구·확대·가상 키보드·모션 감소 대응을 명시한다.

|---|---|
| 직관성 | 아이가 시범과 화면 단서로 주요 행동·선택 결과·뒤로 가기를 찾을 수 있는지 검토 |
| 발견 경험 | 계획한 행동·작은 변화·의미가 연결되고 움직임·소리 없이도 완료 가능 |
| 커스텀 외형 | 기본 폼을 그대로 나열하지 않고 활동에 맞는 일관된 스타일 적용, 예외 이유 기록 |
| 상태 | 선택·눌림·비활성·오류·포커스가 구분되고 중복 입력으로 상태가 꼬이지 않음 |
| 입력·접근성 | 터치·키보드·스크린리더로 이름·역할·상태 확인, 포커스 이동·복원 정상 |
| 화면 | 360×640, 390×844, 768×1024, 1024×768, 1280×800에서 잘림·가림·의도하지 않은 가로 스크롤 없음 |
| 확대·입력 | 200% 글자 확대·긴 문구·가상 키보드에서 주요 동작과 닫기 이용 가능 |
| 정서·안전 | 기존 컬러·용어·네이밍 기준 준수, 과도한 자극·비교·중단 압박 없음 |

실제 아동 관찰 없이 직관성이나 정서 효과가 검증됐다고 표시하지 않는다. 개발자 시나리오·기기·보조기술 검증의 실제 실행 범위와 미실행 항목을 구분한다.
