# 🛠 콘텐츠 구현·검증 가이드

## 📖 개요

게임·학습·창작·이야기 활동을 빌드 없이 로컬 정적 서버에서 실행한다. 현재는 아래 구조와 검증 도구의 설계 기준만 존재하며 콘텐츠·포털·브라우저 하네스는 미구현이다.

## 🧩 주요 내용

### 🧱 기본 스택과 구조

HTML/CSS + Vanilla JavaScript ES Modules를 사용한다. 학습 UI·폼·버튼은 DOM을 우선하고 그림·실시간 놀이에 Canvas 2D를 선택한다. Canvas 사용 시 조작 버튼과 상태 설명을 DOM으로 제공한다. Android 스마트폰·태블릿 Chrome과 데스크톱 Chrome을 우선 검증한다. Safari는 보조 호환성 검증 대상으로 둔다.

```text
contents/
  index.html              # 향후 사용자 포털
  catalog.js              # 향후 단일 콘텐츠 목록
  {slug}/
    index.html
    README.md
    src/
      main.js             # 화면 전환·연결
      activity.js         # DOM 없는 규칙·학습 상태
      render.js           # DOM 또는 Canvas 표현
      input.js            # Pointer Events·키보드
      storage.js          # 저장·스키마·복구·삭제
      audio.js            # 필요 시 사운드
    data/                 # 자체 작성 문항·레벨
    assets/               # 자체 제작 또는 사용 권한 확인 자료
```

필요한 파일만 만든다. 외부 CDN·빌드 도구·서버는 기본 사용하지 않는다. 의존성이 필요하면 이유·버전·라이선스·오프라인 배치 경로를 계획에 명시한다. 공통 모듈 도입은 실제 반복 책임이 확인될 때 검토한다.

### 📐 구현 규칙

- 사용자 화면은 [Fascinating UI 가이드](guide-ui-design.md)를 필수 적용한다. 브라우저 기본 INPUT·SELECT 외형의 나열 대신 활동에 맞는 커스텀 UI를 구성하되 의미 있는 HTML과 표준 조작을 유지한다.
- 색상·문구·네이밍은 [아동 UX·안전 기준](guide-child-safety.md)의 정서·표현 기준을 항상 적용한다. 콘텐츠·캐릭터·단계·버튼·접근성 이름까지 계획과 실제 화면을 대조하고, 변경 시 함께 갱신한다.
- 시범은 반복·건너뛰기 가능하며 처음부터 긴 설명문을 요구하지 않는다.
- 상태 전이와 정답·완료 판정을 렌더링에서 분리한다. 빠른 연속 입력으로 중복 점수·중복 진행이 발생하지 않게 한다.
- 애니메이션은 `requestAnimationFrame`과 경과 시간으로 처리하고 탭 비활성 시 일시정지한다.
- Pointer Events의 취소·포인터 이탈과 화면 회전을 처리한다. Canvas는 DPR·크기 변경·좌표 변환을 반영한다.
- 새로고침 후 복원은 유효한 상태만 허용하고 버전 불일치·손상·저장 차단에 대응한다. 저장이 필수 실행 조건이 되지 않게 한다.
- 접근성을 실제 DOM 의미·키보드·포커스로 구현한다. 포털로 돌아오기와 활동 종료는 항상 찾기 쉽게 둔다.
- 콘텐츠 README에 연령·활동 목표·조작·실행·저장·삭제·에셋 출처·알려진 한계를 기록한다.

### 🚀 실행

```bash
python3 -m http.server 7904 --bind 127.0.0.1
```

문서는 `/docs/guide/guide.html`, 향후 콘텐츠는 `/contents/{slug}/`에서 확인한다. ES Modules는 `file://` 대신 HTTP로 실행한다. 정적 서버 접근 이후 외부 통신 없이 동작하는 것을 기본으로 하며, 설치형 PWA나 서버 없는 재접속 캐시는 별도 범위다.

| 시작·종료 | 시범→활동→완료→다시 하기·목록 흐름 정상 |
| 규칙·학습 | 정답·오답·힌트·마지막 문항·빈 데이터·중복 입력 처리 정확 |
| 정서·표현 | 팔레트 역할·식별성 확인, 이름·문구가 연령에 맞고 비교·낙인·중단 압박·고정관념·효능 단정 없음 |
| 문항 품질 | 오답 표시·정답 근거·언어·수량·그림 대응 모호함 없음 |
| 입력 | 탭·드래그 대안·키보드와 취소 입력 정상 |
| 화면 | 360×640, 390×844, 768×1024, 1024×768, 1280×800에서 조작 가능 |
| Android Chrome | 실제 Android 스마트폰·태블릿에서 입력·음원·저장 확인, 미확인 기기 명시 |
| 보조 호환성 | 이용 가능한 iOS Safari 등에서 확인하고 미실행 환경 명시 |
| 접근성 | 포커스·이름·색상 외 단서·음소거·모션 감소·확대 확인 |
| 저장 | 새로고침·손상값·저장 차단·삭제 후 다른 콘텐츠 데이터 유지 |
| 중단 | 탭 이탈·복귀·화면 회전 시 진행·타이머 정상 |
| 안전 | 개인정보 입력·추적·광고·외부 요청 없음, 필요한 보호자 게이트 우회 경로 점검 |
| 콘솔 | 오류·누락 리소스·의도하지 않은 자동재생 경고 없음 |
| 표현 | 원작 리소스 미포함, 자체 문항·에셋 라이선스 기록 |

JS가 생기면 `node --check`로 문법을 확인한다. 규칙 검증은 `tools/logic/{slug}.mjs`, 실제 입력 검증은 `tools/play/{slug}.mjs`에 구성하되 구현을 그대로 되풀이하는 테스트보다 오답·생성 불변식·상태 복원 같은 위험을 검증한다. Chrome 모바일 에뮬레이션은 실제 Android 기기 검증을 대신하지 않는다.

결과는 `test/{TS}-{slug}-check.md`에 환경·절차·기대값·실제값·성공/실패/미실행·증거 경로로 남긴다. 스크린샷만으로 기능 검증을 대체하지 않는다. 아동 직접 관찰이 없으면 개발자 시나리오 검증으로 명시한다.

### 🔄 완료 처리

콘텐츠 README에 컬러 컨셉·이름의 의미·대표 피드백 문구와 검토 결과를 기록한다. 콘텐츠 README, `GLANCE.md` 목록, 계획·리뷰 목차를 갱신한다. 포털 도입 후 카탈로그에는 `slug`, 자체 이름, 유형, 연령, 짧은 설명, 경로, 태그, 자체 썸네일을 관리한다. 사용자 화면에 테스트 결과·개발 상태·원작 상표를 표시하지 않는다.
