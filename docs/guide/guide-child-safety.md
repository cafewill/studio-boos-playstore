# 🛡 아동 UX·학습·안전 기준

## 📖 개요

아동이 혼자 시도하고 실수 후 다시 탐색할 수 있도록 설계한다. 아래 UX 수치는 프로젝트 내부 기본값이며 Google Play 심사 기준이나 법적 인증을 뜻하지 않는다.

## 🧩 주요 내용

### 🧒 연령별 설계

| 구간 | 프로젝트 기본 방향 |
|---|---|
| 5세 이하 | 기본 설계는 3–5세 중심. 글 없이 시각 시범·한 번 탭·간단한 짝 맞추기. 3세 미만 대상은 별도 설계 |
| 6–8세 | 짧은 문장·단계별 힌트·수량과 규칙 탐색, 드래그 대체 입력 |
| 9–12세 | 다단계 문제·창작·전략, 선택 가능한 난이도와 이유 설명 |

연령은 설계 가설이며 아이마다 읽기·인지·운동 능력이 다르다. 실제 사용자 관찰 전에는 연령 적합성 검증 완료로 표시하지 않는다.

### 🧠 학습·놀이 피드백

- 목표를 “수학 능력 향상” 대신 “1–5개 물체를 세고 대응 숫자를 고른다”처럼 관찰 가능한 행동으로 쓴다.
- 정답 위치·색상만 외워 풀리지 않도록 배열을 바꾸고 문항의 모호함을 점검한다.
- 오답은 감점·큰 경고음 대신 짧은 설명·시각 힌트·다시 시도로 연결한다.
- 기본 모드는 제한 시간·목숨 소진·공개 순위 없이 탐색을 허용한다.
- 짧은 활동 후 자연스럽게 종료·다시 하기·목록으로 돌아가기를 제공한다. 연속 출석 상실·무작위 유료 보상·중단 압박은 넣지 않는다.
- 성적을 지능·발달 상태·장애 여부로 해석하거나 진단하지 않는다.

### 🎨 정서 함양을 고려한 컬러 컨셉

모든 콘텐츠에서 안정감·호기심·자율성·공감을 지원하는 시각 환경을 설계 목표로 삼는다. 다음 기준은 내부 디자인 원칙이며 특정 색상이 정서·인지 발달을 개선한다는 과학적 효과를 보장하지 않는다. 연령·개인 선호·문화·사용 환경을 함께 고려한다.

- 배경·표면·본문·주요 행동·보조 강조·상태 표시의 역할을 나누고, HEX 값과 사용 목적을 계획에 기록한다. 적은 수의 색을 일관되게 사용한다.
- 넓은 배경은 눈에 부담이 적도록 명도·채도를 조절하고, 높은 채도의 색은 중요한 대상·행동에 제한적으로 사용한다. 화면 전체의 원색·네온색·동시 강조를 피한다.
- 밝고 부드러운 색을 사용하더라도 글자·버튼·포커스의 식별성을 확보한다. 파스텔색이라는 이유만으로 접근성을 충족했다고 판단하지 않는다.
- 오답을 화면 전체의 빨간색·위협적인 섬광으로 표시하지 않는다. 차분한 안내와 모양·아이콘·문구를 함께 제공한다. 안전상 주의 표시는 상황에 맞게 명확히 구분한다.
- 색에 성별·우열·도덕적 가치를 고정하지 않는다. 감정 활동에서는 “슬픔은 나쁜 색”처럼 감정을 평가하거나 특정 감정과 색의 연결을 정답으로 강요하지 않는다.

| 역할 | 시작용 색상 예시 | 적용 원칙 |
|---|---|---|
| 배경·표면 | 크림 `#FFF8EE`, 흰색 `#FFFFFF` | 활동 대상과 여백을 구분 |
| 본문 | 짙은 남청 `#243746` | 밝은 배경에서 읽기 쉽게 배치 |
| 주요 행동 | 짙은 청록 `#246B63` | 버튼 문구·상태별 대비를 실제 확인 |
| 탐색·장식 | 연한 하늘 `#DCEEF8`, 살구 `#F6D9C5` | 정보 전달을 장식색 하나에 의존하지 않음 |

예시는 출발점이며 고정 브랜드나 검증 완료 팔레트가 아니다. 실제 조합의 텍스트·경계·비활성·포커스 대비와 모바일 화면을 확인하고 콘텐츠 분위기에 맞춰 조정한다.

### 💬 정서를 존중하는 용어와 피드백

- 연령에 맞는 짧고 구체적인 한국어와 일관된 동사를 사용한다. 5세 이하 대상은 문구만 읽어야 진행할 수 없도록 시범·그림을 함께 제공한다.
- 아이의 능력·인격을 평가하지 않고 시도·관찰·과정·다음 행동을 안내한다. 과장된 능력 칭찬이나 타인과의 비교 대신 구체적 행동을 짚는다.
- 오답·도움 요청·쉬기·종료를 자연스러운 선택으로 다룬다. 죄책감·실망·보상 상실로 계속 이용하도록 압박하지 않는다.
- 감정에는 옳고 그름을 매기지 않는다. “속상할 수 있어. 잠깐 쉬어도 괜찮아”처럼 감정을 인정하고 선택권을 제공하되 아이의 감정 상태를 단정하지 않는다.
- 성별·외모·가족 형태·장애·문화·학습 속도를 희화화하거나 우열로 표현하지 않는다. 보호자를 부를 때 다양한 돌봄 관계를 고려해 “보호자와 함께” 같은 표현을 사용한다.

| 상황 | 피할 표현 | 권장 예시 |
|---|---|---|
| 오답 | “틀렸어! 이것도 몰라?” | “모양을 살펴보고 다시 골라 볼까?” |
| 완료 | “넌 천재야! 친구보다 잘했어!” | “같은 모양을 모두 찾았어!” |
| 도움 | “이것도 못하면 힌트” | “힌트 보기”, “함께 살펴보기” |
| 중단 | “지금 나가면 친구가 슬퍼해” | “여기서 쉬기”, “목록으로 돌아가기” |
| 난이도 | “바보 단계”, “천재만 도전” | “처음 해보기”, “조금 더 도전하기” |

예시를 모든 연령에 그대로 적용하지 않고 읽기 수준과 상황에 맞춰 길이·말투를 조정한다. 버튼은 실제 동작을 정확히 설명한다.

### 🏷 콘텐츠·캐릭터·활동 네이밍

- 콘텐츠명·캐릭터명·단계명·버튼·보상명·포털 소개·접근성 이름까지 같은 기준을 적용한다. 신규 제작뿐 아니라 기존 콘텐츠 수정 시에도 재검토한다.
- 친근한 자연·탐색·함께하기·창작의 이미지를 고려하되 실제 활동을 예상할 수 있게 짓는다. 예: “마음 정원 — 감정 살펴보기”, “차근차근 수 놀이터”, “함께 그리는 숲”. 예시는 사용 확정 이름이 아니다.
- 공포·조롱·폭력·서열 경쟁을 부추기는 이름, 성별 고정관념, “IQ 상승 보장”·“발달 치료” 같은 검증되지 않은 효능 표현을 사용하지 않는다.
- 원작 상표·유명 캐릭터와 혼동될 이름을 피하고, 공개 배포 전 유사 이름·상표를 확인한다. 이름의 독창성·사용 가능성을 검증 전 확정하지 않는다.
- 사용자 표시 이름은 쉬운 한국어를 우선하고 기술 슬러그는 별도 자체 영문 이름으로 정한다. 이름만으로 이해하기 어려우면 짧은 활동 설명을 붙인다.

### ✅ 정서·표현 검토 기록

리뷰·계획에는 목표 정서 경험, 팔레트 역할·색상 값·선정 이유, 자체 이름과 의미, 시작·정답·오답·힌트·종료 문구를 남긴다. 원작의 자극적 연출·비교·압박을 발견하면 자체 구현의 대체안을 명시한다.

완료 전에는 화면·문항·캐릭터 대사·접근성 이름을 함께 확인한다. 팔레트의 식별성, 존중하는 표현, 자율적인 중단, 성별·문화적 고정관념 여부를 점검하고 결과·수정 내용·미확인 항목을 기록한다. 개발자 검토와 아동·보호자 관찰 결과를 구분하고, 관찰하지 않은 정서·발달 효과를 검증 완료로 표시하지 않는다.

### 🎛 입력·접근성

커스텀 UI의 발견 경험과 반응형 설계는 [Fascinating UI 가이드](guide-ui-design.md)를 함께 따른다. 절제된 표현·자율적 중단·과도한 자극 방지 기준은 커스텀 컴포넌트와 연출에도 동일하게 적용한다.

- 주요 터치 영역은 최소 48×48 CSS px, 인접 영역 간격은 8px를 목표로 한다. 실제 기기에서 오터치를 확인한다.
- 드래그에는 탭 선택 → 목적지 탭 대안을 제공한다. 드래그 취소와 화면 밖 이동도 복구한다.
- 아이콘에 짧은 텍스트나 접근 가능한 이름을 제공한다. 색상·소리 하나만으로 정답·상태를 전달하지 않는다.
- 기본 본문 18px 이상을 시작점으로 하고 확대·작은 화면을 점검한다. DOM 버튼·포커스 표시·키보드 탐색을 우선한다.
- 소리는 사용자 동작 후 활성화하며 음소거를 제공한다. 소리 없이도 완료할 수 있어야 한다.
- `prefers-reduced-motion`에 대응하고 강한 깜빡임·갑작스러운 큰 소리·과도한 축하 연출을 피한다.

### 🔒 데이터와 보호자 영역

| 영역 | 기본 기준 |
|---|---|
| 데이터 | 이름·생년월일·사진·음성·위치·연락처를 요구하거나 수집하지 않음 |
| 외부 통신 | 광고·분석·추적 SDK, 외부 글꼴·CDN·API 호출 없음 |
| 저장 | 기기 내 설정·최소 진행만 저장, 키 `{slug}:v2:*` (추가 버전은 공통 변환 규약 적용), 손상·차단 시 초기값 복구 |
| 삭제 | 보호자 영역에서 저장 범위 안내 후 삭제 확인, 해당 콘텐츠 키만 삭제 |
| 계정·소셜 | 로그인·채팅·업로드·친구·외부 공유 없음 |
| 보호자 영역 | 설정 초기화·외부 정보 등 성인 동작 분리. 게이트는 세션 한정, 새로고침·이탈 시 잠금 |

보호자 게이트는 우발적 진입을 줄이는 장치다. 법적 보호자 동의·본인 인증·연령 확인을 대신하지 않는다. 생년월일 입력을 요구하는 방식은 사용하지 않는다. MVP에 외부 링크가 없다면 링크만을 위한 게이트를 추가할 필요는 없다.

### 🛡 Google Play 공식 기준과 프로젝트 기준

2026년 11월 21일 확인. Google Play는 대상 연령에 아동을 포함하는 앱에 Families 정책 준수를 요구한다. Play Console의 대상 연령 선택 구간 중 본 프로젝트는 5세 이하·6–8세·9–12세를 참고한다. 스토어 콘텐츠 등급과 개발자가 선언하는 대상 연령, 실제 활동의 권장 연령은 별개로 기록한다.

대상 연령·데이터 보안·콘텐츠 등급 관련 신고는 실제 앱과 일치해야 한다. 아동 대상 광고에는 별도의 SDK·수익화 정책이 적용되며, 본 프로젝트 로컬 MVP는 광고·분석·구매·계정을 모두 제외한다. 보호자 영역과 게이트는 내부 UX 기준이며 보호자 동의나 연령 확인을 대신하지 않는다.

- [Google Play 대상 연령 및 콘텐츠 설정](https://support.google.com/googleplay/android-developer/answer/9867159?hl=ko)
- [Google Play Families 정책](https://support.google.com/googleplay/android-developer/answer/9893335?hl=ko)
- [Google Play 콘텐츠 등급 요구사항](https://support.google.com/googleplay/android-developer/answer/9859655?hl=ko)

공식 정책과 내부 구현 원칙을 구분한다. Android 앱 출시를 결정할 때 최신 심사·개인정보·대상 국가 요구사항을 다시 검토한다. 로컬 체크리스트 통과를 Google Play 승인이나 법적 적합성 보장으로 표시하지 않는다.

### 🌱 확장 활동의 표현·학습 경계

- 낱말 연결은 자체 선정한 일상 단어의 시각적 탐색이다. 읽기 발달·발음·음운 교육의 검증된 프로그램이라고 표시하지 않는다. 보호자와 함께 읽을 수 있고 속도·점수·오답 벌점을 넣지 않는다.
- 생활 순서는 가능한 한 가지 흐름을 연습한다. 가정별 습관·식사·휴식 방식의 옳고 그름을 평가하지 않는다. 조리 도구·불·투약·의료 행위 모방은 넣지 않으며 실제 이동·장보기는 어른과 함께하는 문구를 사용한다.
- 공간·소품 창작은 성별·외모 평가 없이 누구나 선택한다. 서로 다른 소품 세 가지라는 완료 조건을 화면에 설명하며, 특정 배치·색 조합의 우열이나 사회적 점수를 부여하지 않는다.
- 시스템 그림 문자는 기기마다 달라질 수 있다. 모든 조작에 텍스트 이름을 함께 제공하고 실제 Android에서 의미·크기·표시 누락 여부를 확인한다. 아동 적합성은 실제 관찰 전 가설로 관리한다.

### 🧪 재료·리듬·조합·프레임의 안전 경계

- 재료 쌓기는 가상 그림 순서 비교다. 불·칼·실제 식재료·알레르기 판단을 요구하지 않고, 완성을 실제 조리 능력이나 식습관 검증으로 표현하지 않는다.
- 리듬은 소리 기본 꺼짐, 한 박씩 사용자 동작으로만 진행한다. 시각적 켜짐·박 번호·확인 수를 제공해 듣지 않아도 완료 가능하게 한다. 기존 곡·보컬·녹음·공유를 사용하지 않는다.
- 조합 결과는 정의에 명시한 단순 가상 모델 또는 상상 조합이다. 실제 화학·물리 실험·교육과정의 정확성을 보증하거나 실제 물건을 섞도록 지시하지 않는다.
- 프레임은 아홉 자리의 자체 기호를 네 장에 배치하고 수동으로 넘긴다. 카메라·사진·얼굴·영상 업로드·자동 반복 재생 없이 위치 변화를 비교한다.
- 돌봄 확장은 인형 놀이와 어른에게 도움 요청에 한정한다. 실제 아기·반려동물 돌봄 지침이나 의료 행위 교육을 대체하지 않는다. 읽기·첫 글자 확장은 발음·파닉스·문해 발달 효과가 검증된 프로그램으로 표시하지 않는다.
